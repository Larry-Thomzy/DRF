TOPIC 12 — SETTING UP THE DRF PROJECT

1. Django Project Structure

After installing Django and Django REST Framework, we need to understand the structure of our project.

Our eCommerce project looks like this:

ecommerce/
├── ecommerce/
│   ├── **init**.py
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   └── wsgi.py
├── manage.py
└── venv/

2. manage.py

manage.py is the main command-line tool for controlling our Django project.

We use it to run commands such as:

python manage.py runserver
python manage.py startapp products
python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser

Think of manage.py as the control center for our Django project.

3. settings.py

settings.py contains the configuration of our Django project.

It controls things such as:

* Installed apps
* Database configuration
* Middleware
* Templates
* Static files
* Time zone
* Security settings
* Django REST Framework settings

For example, when we create an app, we add it to INSTALLED_APPS.

4. urls.py

urls.py controls URL routing.

It tells Django which view should handle a particular URL.

For example:

/api/products/
/api/users/
/api/orders/

The URL is connected to a view that handles the request.

5. asgi.py and wsgi.py

These files are used when deploying the Django application to a server.

For now, we don't need to work with them.

Just remember:

asgi.py → ASGI deployment
wsgi.py → WSGI deployment

6. Django Project vs Django App

This is very important.

PROJECT = The entire eCommerce system.

APP = A specific part of the system.

Our eCommerce project could contain apps such as:

* products
* users
* orders
* cart
* payments
* reviews

Example:

ecommerce/
├── ecommerce/
├── products/
├── users/
├── orders/
├── cart/
└── payments/

The project contains multiple apps.

7. Create Our First App

We are going to create a products app.

Run:

python manage.py startapp products

Django will create:

products/	
├── **init**.py
├── admin.py
├── apps.py
├── migrations/
│   └── **init**.py
├── models.py
├── tests.py
└── views.py

8. Register the App

Open:

ecommerce/settings.py

Find:

INSTALLED_APPS = [
...
]

Add:

"products",

Example:

INSTALLED_APPS = [
"django.contrib.admin",
"django.contrib.auth",
"django.contrib.contenttypes",
"django.contrib.sessions",
"django.contrib.messages",
"django.contrib.staticfiles",
"rest_framework",
"products",
]

9. Create Our First DRF API Endpoint

Open:

products/views.py

Add:

from rest_framework.response import Response
from rest_framework.decorators import api_view

@api_view(["GET"])
def hello_api(request):
return Response({
"message": "Hello from our eCommerce API!"
})

What is happening?

@api_view(["GET"])

This tells DRF that our view accepts GET requests.

Response()

This creates an API response.

The dictionary:

{
"message": "Hello from our eCommerce API!"
}

will be returned as JSON.

10. Create URLs for the Products App

Create:

products/urls.py

Add:

from django.urls import path
from .views import hello_api

urlpatterns = [
path("hello/", hello_api),
]

This connects:

/hello/

to:

hello_api()

11. Connect App URLs to the Main Project

Open:

ecommerce/urls.py

Change it to:

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
path("admin/", admin.site.urls),
path("api/", include("products.urls")),
]

Now Django knows that URLs beginning with:

/api/

should be handled by:

products/urls.py

12. Run the Server

Run:

python manage.py runserver

You should see something similar to:

Starting development server at http://127.0.0.1:8000/

13. Test the API

Open your browser and visit:

http://127.0.0.1:8000/api/hello/

You should receive:

{
"message": "Hello from our eCommerce API!"
}

14. Understand the Request Flow

When we visit:

GET /api/hello/

The request flows like this:

Browser
↓
ecommerce/urls.py
↓
products/urls.py
↓
hello_api()
↓
DRF Response
↓
JSON
↓
Browser
