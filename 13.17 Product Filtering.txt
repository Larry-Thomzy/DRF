
‎TOPIC 13.17: PRODUCT FILTERING WITH DJANGO REST FRAMEWORK
‎
‎1. Introduction
‎
‎Product filtering is the process of retrieving specific products from a database based on conditions supplied by a client.
‎
‎In an eCommerce application, customers should be able to narrow down products based on criteria such as:
‎
‎- Minimum and maximum price.
‎- Product availability.
‎- Product category.
‎- Brand.
‎- Other product attributes.
‎
‎Instead of retrieving every product, the API returns only products that match the requested conditions.
‎
‎Example
‎
‎Imagine our database contains:
‎
‎Product| Price| Stock
‎Keyboard| 15000| 10
‎Mouse| 5000| 0
‎Monitor| 85000| 5
‎Headphones| 25000| 12
‎
‎A customer wants products costing between ₦10,000 and ₦30,000.
‎
‎Instead of retrieving all four products, filtering returns:
‎
‎- Keyboard
‎- Headphones
‎
‎---
‎
‎2. Understanding Query Parameters
‎
‎Query parameters are additional values attached to a URL to provide information to an API.
‎
‎They begin with a question mark ("?") and multiple parameters are separated using an ampersand ("&").
‎
‎Examples
‎
‎/api/products/?min_price=10000
‎
‎Returns products costing at least 10,000.
‎
‎/api/products/?max_price=30000
‎
‎Returns products costing at most 30,000.
‎
‎/api/products/?min_price=10000&max_price=30000
‎
‎Returns products within the specified price range.
‎
‎Important terminology
‎
‎- "?" — begins the query parameter section.
‎- "min_price" — parameter name.
‎- "10000" — parameter value.
‎- "&" — separates multiple parameters.
‎
‎---
‎
‎3. Understanding Django ORM Filtering
‎
‎Django provides a method called ".filter()" that allows us to retrieve database records matching specified conditions.
‎
‎Syntax:
‎
‎Model.objects.filter(field=value)
‎
‎Example:
‎
‎Product.objects.filter(price=15000)
‎
‎Returns products whose price is exactly 15,000.
‎
‎Common Django field lookups
‎
‎Lookup| Meaning
‎"exact"| Exact match
‎"gt"| Greater than
‎"gte"| Greater than or equal to
‎"lt"| Less than
‎"lte"| Less than or equal to
‎"contains"| Contains a specific string
‎"icontains"| Case-insensitive string search
‎"in"| Matches any value in a collection
‎
‎Examples:
‎
‎Product.objects.filter(price__gt=10000)
‎Product.objects.filter(price__gte=10000)
‎Product.objects.filter(price__lt=50000)
‎Product.objects.filter(price__lte=50000)
‎Product.objects.filter(name__icontains="keyboard")
‎
‎Notice the double underscore ("__") between the field name and lookup.
‎

‎
‎4. Filtering Products Using Query Parameters
‎
‎We can access query parameters in Django REST Framework through:
‎
‎request.query_params
‎
‎Example:
‎
‎min_price = request.query_params.get('min_price')
‎
‎This retrieves the value of "min_price" from the request URL.
‎
‎If the parameter doesn't exist, ".get()" returns "None".
‎
‎Example implementation
‎
‎Inside the GET section of our existing "products_list" view:
‎
‎products = Product.objects.all()
‎
‎min_price = request.query_params.get('min_price')
‎
‎if min_price:
‎    products = products.filter(price__gte=min_price)
‎
‎serializer = ProductSerializer(products, many=True)
‎
‎return Response(serializer.data)
‎
‎Explanation
‎
‎1. "Product.objects.all()" retrieves the initial product queryset.
‎2. "request.query_params.get('min_price')" retrieves the requested minimum price.
‎3. "if min_price:" checks whether a minimum price was provided.
‎4. ".filter(price__gte=min_price)" narrows the queryset.
‎5. The serializer converts the resulting products into response data.
‎6. "Response(serializer.data)" returns the filtered products.
‎
‎---
‎
‎5. Combining Multiple Filters
‎
‎We can apply multiple filtering conditions to the same queryset.
‎
‎Example:
‎
‎products = Product.objects.all()
‎
‎min_price = request.query_params.get('min_price')
‎max_price = request.query_params.get('max_price')
‎
‎if min_price:
‎    products = products.filter(price__gte=min_price)
‎
‎if max_price:
‎    products = products.filter(price__lte=max_price)
‎
‎When both conditions are provided, Django applies both conditions.
‎
‎This is equivalent to an AND operation.
‎
‎For example:
‎
‎/api/products/?min_price=10000&max_price=30000
‎
‎The returned products must satisfy both conditions.
‎
‎---
‎
‎6. Filtering by Stock Availability
‎
‎Our Product model contains a "stock" field.
‎
‎We can use it to distinguish between available and unavailable products.
‎
‎Example:
‎
‎products = Product.objects.filter(stock__gt=0)
‎
‎Returns products that have stock available.
‎
‎To retrieve products that are out of stock:
‎
‎products = Product.objects.filter(stock=0)
‎
‎A query parameter could make this functionality available through the API.
‎
‎For example:
‎
‎/api/products/?in_stock=true
‎
‎---
‎
‎7. Important Concepts to Remember
‎
‎QuerySet
‎
‎A QuerySet represents a collection of database objects returned by Django's ORM.
‎
‎Example:
‎
‎products = Product.objects.all()
‎
‎Chaining filters
‎
‎Multiple filters can be applied to the same QuerySet.
‎
‎products = Product.objects.filter(price__gte=10000)
‎products = products.filter(stock__gt=0)
‎
‎The resulting QuerySet contains products that satisfy both conditions.
‎
‎Lazy evaluation
‎
‎Django QuerySets are lazy.
‎
‎This means Django generally does not execute the database query immediately when ".filter()" is called. The query is executed when the results are evaluated.

‎8. eCommerce Project Application
‎
‎Our objective is to upgrade the existing product-list endpoint.
‎
‎Current endpoint:
‎
‎GET /api/products/
‎
‎We want to support:
‎
‎Request| Expected result
‎"/api/products/"| All products
‎"/api/products/?min_price=10000"| Products costing at least 10,000
‎"/api/products/?max_price=30000"| Products costing at most 30,000
‎"/api/products/?min_price=10000&max_price=30000"| Products within the price range
‎"/api/products/?in_stock=true"| Products currently in stock
‎"/api/products/?in_stock=false"| Products currently out of stock
‎
‎Implementation requirements
‎
‎1. Preserve the existing GET and POST functionality.
‎2. Apply filtering only when the corresponding query parameter is supplied.
‎3. Allow multiple filters to work together.
‎4. Validate incoming filter values so invalid prices or boolean values do not produce server errors.
‎5. Return appropriate API responses.
‎6. Ensure the existing POST functionality continues to work.
‎
‎Note: We will implement these features incrementally in our existing function-based view. We are not introducing a new architecture or refactoring the project for this lesson.
